# MCP 调用约定

用于首次真实调用平台 MCP，以及排查参数、分页、修订、会话或版本差异。当前会话公布的 schema 和返回值是调用依据；本文提供操作语义，不替代 schema。

## 主动发现并调用工具

平台资源的查询、诊断和修改请求本身就是执行意图。目标与权限已明确时，主动调用对应 MCP，不要求用户补充“请调用工具”。诊断中可先做已知目标的必要只读检查，症状、时间段等缺失信息按需补充，不让可独立开展的检查停在提问。

1. 查看实际工具清单。客户端有工具搜索或延迟发现接口时，用平台名称 `collaboration_platform` / `collaboration-platform` 和本次模块关键词搜索；工具可能带服务或客户端前缀，不依赖固定前缀。核对所属服务与目标，避免将其他数据库或缓存 MCP 的同名工具当作平台工具。
2. 只取得本次需要的工具与 schema。服务器查 `server_*`，关系型数据库查 `db_*`，Redis 查 `cache_*`，Word 查 `doc_*`，Excel 查 `sheet_*`；项目与知识内容按对应模块查找。只读相关参考，不把全部工具定义复制进提示。
3. 使用已知 ID 做小范围上下文读取。工具支持时先核对目标、项目、有效权限与就绪状态，再打开或复用资产会话，执行并保存实际返回的标识。

| 已知目标 | 首次读取与后续路径（仅在实际提供这些工具时） |
| --- | --- |
| 服务器 ID | `server_context_get` → 打开 / 复用会话 → 获准的诊断命令 → 查询原命令结果 |
| 数据库连接 ID | `db_context_get` → 打开 / 复用数据库会话 → 必要 SQL → 原语句结果 |
| Redis 连接 ID | `cache_context_get` → 打开 / 复用缓存会话 → 必要指标、慢日志或目标 Key |
| Word 文档 ID | `doc_get` 的大纲或 `doc_find` → 目标正文 → 按任务编辑与回读 |
| Excel 工作簿 ID | `sheet_get` → `sheet_find` 或指定区域 → 按任务计算、编辑与回读 |

资源列表与工具列表不是同一回事。`list_mcp_resources` / 资源模板返回空，不足以证明服务没有工具；使用客户端实际提供的工具发现机制。Skill 文件、MCP 配置条目和 Desktop 进程存在，也不能单独证明当前会话已经可调用 MCP。

## 工具缺失时的连接排查

- 先完成一次有针对性的工具发现，区分整个平台工具缺失与某个模块缺失。没有工具发现接口时，明确当前只能检查已公布清单，不声称查过未提供的能力。
- 有获准的本地读取能力时，自行检查当前客户端实际配置来源、启用状态、程序路径或本机端点，以及相关启动错误。区分用户级与项目级配置、当前主机与工作目录；用户级未列出条目，不能直接推断项目级也没有配置。
- 配置存在但工具未加载时，检查当前聊天是否使用该配置、MCP 握手 / 启动是否报错；只有部分模块缺失时，核对能力选项、模块开关、权限与项目范围。没有日志证据就保留原因未定，不把猜测写成结论。
- 客户端提供实际可用的状态查询或重载能力，且操作在已有授权内、不会中断其他任务的在用连接时，可执行一次有针对性的检查或重载，再重新发现工具。否则给出当前客户端或 Desktop“设置 → AI 接入”的具体处理步骤。没有状态变化时不反复重连或重复搜索。
- 配置与日志仅报告相关的脱敏结果，不输出令牌、完整随机路径、密码、环境变量值或含凭据的参数。排查不扩大项目白名单、资产权限或操作范围。
- 恢复后完成一次目标的最小必要读取，再继续原任务。仍缺失时报告“实际发现了什么、配置在哪一层、已知错误、缺少哪些工具、下一步是什么”；不能把未执行的诊断说成已完成，也不能把转用 UI 或本机源码分析作为已调用 MCP 的证据。

## 找到对象与可用能力

有明确项目与对象 ID 时，只读取对应对象确认归属。需要查找时使用相关列表或支持的筛选，小页开始；不要为了一个文档先遍历全部产品、项目、资产和规范。

- 项目范围工具按 schema 传入已授权的 `project_id`。部分资产、脚本和 Office 工具允许省略，默认指向会话项目；跨已授权项目操作时显式指定，后续调用保持同一项目。
- 产品级工具、项目列表等是否带项目参数按各自 schema 判断，不能给所有工具机械添加 `project_id`。
- 一个 `document_id` 可能是节点 Markdown 文档，也可能是 Office 文档；结合来源工具、对象类型和所属项目判断，不能只看字段名。
- 资产的 `connection_id`、脚本 SDK 中的本地连接 ID、云端资源 ID 不一定相同；分别使用对应上下文返回的字段，不自行转换或替换。
- 工具缺失按前述发现与连接排查处理；确认未提供后停止猜测工具名。版本、模块、套餐、权限预设或对象授权变化后再刷新相关能力。
- 不将旧版本的项目任务、需求、Bug 或变更集接口设为所有任务的必需前置步骤；只有当前会话确实提供时，才按其真实约束办理。

## 分页与预算

| 结果族 | 常见请求与继续方式 | 完成判断 |
| --- | --- | --- |
| 项目、导图、节点、关联等普通列表 | `cursor`、`page_size`，使用返回的 `next_cursor` | 依实际 `is_complete` / `next_cursor` 判断 |
| `content_*` 内容树 | 首次绑定 `revision`（如需要），后续沿用 `subtree_snapshot_id` 与 `cursor`；可传 `token_budget` | 完整子树需所有页完成 |
| `doc_get` 正文 | `after` 为块 ID，`limit` 为块数；用返回的 `next_after` 继续 | `is_complete` |
| 数据库结果 | 原 `db_session_id`、`statement_id`，按 `next_cursor` 续读 | `execution_is_complete` 与 `result_is_complete` 分别表示执行、结果读取完成 |
| 脚本输出 | 将返回 `cursor` 用作下一次 `after` | `has_more` 为当前可读更多，`is_complete` 为输出真正结束 |
| 流程输出 | 返回的数值 `cursor` 原样继续，可加目标 `node_id` | 同时考虑 `has_more`、`is_complete` 与运行状态 |
| Redis SCAN | 保留本会话的字符串 `cursor` | 返回 `0` 表示扫描结束；中途空页不能当结束 |
| Redis 订阅消息 | `after` 使用返回游标 | 检查消息缺口、丢弃数量和订阅状态；订阅不会自然读完 |

不同接口的游标可能是字符串、整数或块 ID，不可混用、猜测或自行累加。并非所有列表都支持分页，只有 schema 提供时才发送分页字段。

`QUERY_TOO_LARGE` 可能表示构造整个子树的范围超限，此时选择更近的内容根或逐层读取；仅减小 `page_size` 或 `token_budget` 未必解决服务端遍历范围问题。

普通列表可从 10–20 项开始，正文可从 10–30 块开始；这些是起始建议，不是固定要求。内容树可先用约 2,000–4,000 的 `token_budget`，必要时调整。当前内容预算按字节估算，不能作为精确 token 计数；单项过大仍可能失败。

需要全量结论时把必要页读完；只需一个目标时定位成功即可停止，并说明覆盖范围。保留快照的一致性；快照失效后重新从该局部建立，不能把不同快照分页混成一次完整读取。

## 修订与并发修改

| 操作 | `base_revision` 通常属于 |
| --- | --- |
| 新建导图或导图文件夹 | 项目 |
| 新建节点 | 所在导图 |
| 新建节点 Markdown 文档 | 父节点 |
| 修改或删除已有导图、节点、文档、连线、业务线 | 被修改对象 |
| 修改 Word、Excel、脚本或流程 | 对应文档、脚本或流程 |
| 新建流程说明文档 | 父流程；修改已有说明时使用说明文档自身修订 |

接口未要求修订时，不自行增加该参数。节点 Markdown 与 Office 的创建规则不同，不把父节点修订硬套在 `doc_create` 或 `sheet_create` 上。

优先使用本任务刚读到或成功写入返回的修订。批量创建同级对象时，从每次响应里的项目 / 导图等新修订衔接下一次；缺少所需修订才补读最小父对象，不盲目硬编码递增值。

`VERSION_CONFLICT` 代表并发状态变化。若现有基线不足以证明修改仍适用，读取冲突涉及的最新部分再合并；不能只把 `current_revision` 填回去覆盖他人内容。明确的、不冲突的合并可在现有授权内完成；业务意图冲突才需要用户取舍。

## 超时、重试与结果未知

- 网关一般代填请求 ID / 幂等键，重试可能产生新值。只有 schema 明确提供可控字段时才使用稳定键；不能假设一次失败调用可以安全重复创建。
- 已拿到运行、命令或语句 ID：沿用原 ID 和原资产会话查询状态，不重新提交同一执行。
- 未拿到 ID 但写入可能已发生：按对象列表、修订、运行历史或审计核对。仍无法确定时，保留未知状态并说明核对入口，停止重复写入。
- `VALIDATION_FAILED`、`REQUEST_TOO_LARGE` 或预算失败：按错误修改参数、缩小页或拆分内容；不原样重试。
- `DB_RESULT_PERSIST_FAILED` 表示 SQL 可能已执行但结果保存失败，优先核对原语句及目标数据，不能重发写语句。

运行终态与输出读完是两件事。只需业务结果时，确认终态和必要结构化结果即可；需要完整日志时才读到输出完成。轮询采用合理间隔或可用的等待机制，状态未变化时逐步降低频率。

## 会话与实际权限

同一任务复用现有的服务器、数据库或 Redis 会话。完成且结果已确认后关闭本任务创建的会话；有订阅则取消订阅。不要关闭其他用户或其他任务的会话，也不要在结果未核对前销毁可用证据。

容量已满时优先复用、关闭本任务闲置会话或等待租约释放。MCP 传输重连不能代替资产会话释放。

是否启用 AI 隔离、使用 AI 账号还是获准人工连接，由当前上下文和软件配置决定；账号验证不自动降低高权限账号的实际系统权限。按有效策略执行，不能通过换账号、包装命令、直连或其他工具绕过拒绝。

## 结果与最小报告

列表或先前响应已经包含足够正文与修订时，直接复用，不为遵循示例流程重复调用详情接口。

等价的结构化结果和 JSON 文本只处理一份。保留必要的对象与父对象 ID、修订、游标、运行状态及关键指标，不把原始大结果重复粘贴进回复。

完成报告包含实际完成内容、目标对象 / 运行标识、验证结果和待处理事项；不将提案、草稿、排队、取消、超时或配置导出描述为执行成功。
