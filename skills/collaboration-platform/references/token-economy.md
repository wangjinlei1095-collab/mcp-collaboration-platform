# 节省 token：执行方法与统计口径

用于优化平台与 AI 的使用方式、设计预算或说明节省比例。优先保障任务完整性和结果正确；减少无关输入、重复生成和无效往返，不删去必要验证与证据。

## 把缩减发生在模型读取之前

让平台、SQL 或脚本先完成搜索、筛选、计数与汇总，再返回必要结果。模型已经读完整份大结果后再总结，不能消除该次输入的 token。

本 Skill 采用渐进加载：主入口用于选择任务，只读相关参考文件。不要把所有参考、所有项目规则和完整工具 schema 固定复制到每次提示中。当前客户端已经提供的工具定义也不在提示中再抄一遍。

## 不同对象的低消耗路径

| 对象 | 建议路径 | 需要保留的完整性 |
| --- | --- | --- |
| 项目知识 | 明确 ID → 相关导图 / 节点 → 必要说明；内容子树用预算与快照 | 全图审阅时必须覆盖必要节点与关联 |
| Word | `format=outline` 或 `doc_find` → 目标 blocks → 块编辑 → 小范围回读 | 保留类型、runs 与样式；全文校对不能只看大纲 |
| Excel | `sheet_get` → `sheet_find` / 指定 A1 范围 → 公式或程序汇总 | 保留口径、公式与类型；修改区域未覆盖格可能被清空 |
| 代码 | 路径 / 符号索引与任务 Skill → 必要源码 → 局部修改 | 索引只是位置元数据，必要依赖和验证仍须读取 |
| 脚本 | 列表用途与参数 → 复用 → 参数运行 → 状态 / 结构化结果 | 首次编写、必要源码审阅与执行验证不能省略 |
| 流程 | 复用既有图 → 一次启动 → 目标节点状态与结果 | 修改图需保留完整现状；不能用局部图覆盖 |
| 服务器 | 复用会话 → 有限制的命令输出 → 文件补丁 | 哈希、退出码与目标核对；不虚构文件行范围参数 |
| SQL | 元数据 → 明确列 / WHERE / 聚合 → 结果必要页 | 查询权限、统计口径、截断和必要样本 |
| Redis | 目标 Key / 前缀 → 类型分页 → 指标或新增消息 | 完整扫描终止条件、丢弃与断线缺口 |

## 起始预算与增量读取

以下只是起点，受当前 schema、对象大小和任务覆盖范围约束，不能作为硬性上限：

| 接口 | 可采用的起点 |
| --- | --- |
| 普通分页列表 | `page_size=10` 或 `20`，必要时继续 |
| 内容子树 | `page_size=10`，`token_budget` 约 2,000–4,000，沿用同一快照 |
| Word 正文 | 指定格式，`limit=10`–`30`，按返回 `next_after` 继续 |
| Excel | 明确表头与任务区域，通常先几十至几百格；当前单次最多 5,000 格 |
| 数据库结果 | 先取约 20–50 行或直接聚合，保留真实结果游标 |
| 脚本 / 流程日志 | 先读状态与指标；需要时按游标取约 20–100 条，流程指定目标节点 |
| Redis | 指定 Key / 前缀及必要类型，按有效策略设置小 `limit` |

对不提供这些参数的接口不能硬加 `limit`、`page_size` 或 `token_budget`。分页只是控制单次体积，最终把全部内容反复读完不会自动省总量。

保留当前任务里的对象 ID、修订、已读覆盖范围、快照和游标。等价 JSON 文本和 `structuredContent` 处理一份。响应仍有效时复用；并发修改、权限或版本变化后刷新相关部分，不能用过期信息换取低消耗。

轮询先看结构化状态，有新输出再增量读取；没有变化时合理等待并降低频率。停止条件按任务：只需最终指标无需下载全部成功日志，需要完整证据时再取全。

## 减少重复生成和失败调用

- 用块、单元格区域和文件补丁代替无必要的全文重写。接口只能整体替换时保留完整原有数据，不能擅自传半份。
- 复用已验证的参数化脚本与流程；计算、去重、过滤和批量处理交给程序，向模型返回摘要及异常样本。
- 先看有效权限、参数说明、可执行原因与结果限制，避免生成必然被拒的命令或 SQL。
- 缺少权限、容量、参数错误或状态冲突时按原因处理，不频繁重连或原样重试。
- 范围已明确的任务不先遍历所有产品、项目、文档和资产，不重复读取所有规则。
- 用户配置允许时仅启用需要的工具能力。某些客户端按需加载工具定义，清单缩小的实际 token 收益取决于其实现；不为此自动修改授权。

## 如何给出百分比

实测需要同一任务、相同数据、模型、完成质量与可比的缓存 / 历史上下文条件。记录所有调用的实际输入、输出及计入总量的其他 token，包括工具定义、结果、重试、回读、首次建索引与脚本流程编写。

使用 AI 客户端或模型服务实际返回的 usage；没有真实统计就标为估算。推理 token、缓存 token 若已包含在总字段中，只作为细分展示，不能重复相加。不要将字符数、文件大小或中文字符除以 4 当精确 token。平台 `token_budget` 是按字节估算的预算，也不是模型计数器。

`节省比例 =（对照方案 token − 当前方案 token）÷ 对照方案 token × 100%`

基线为 0 时无有效百分比；当前更高时如实报告负收益。输入、输出可分别比较；只有完整记录整项任务后才报告整体比例。重复使用场景要区分首次成本、单次复用成本和多次累计成本。

例如：某一步对照输入 10,000 token，按需定位后连同额外索引与调用共输入 2,000 token，则该步输入减少 80%。这只是示例计算，不是平台实测。

## 场景估算参考

下表为按内容占比计算的假设，未实测；只适用于列明环节。固定提示、schema、调用与验证开销会影响整项任务收益。

| 能力 | 假设优化后内容占对照量 | 对应环节预计减少 |
| --- | --- | --- |
| 项目知识分支读取 | 节点与说明输入为 20%–50% | 约 50%–80% |
| 分页与内容预算 | 仅需读取的资料为 30%–70% | 约 30%–70% |
| Word 大纲与定位 | 大纲、索引与必要正文为 10%–30% | 约 70%–90% |
| 局部修改 | 实际写入内容为全文重写的 5%–20% | 约 80%–95% |
| Excel 按区域读取 | 结构与必要单元格为 10%–30% | 约 70%–90% |
| 代码索引定位 | 实际代码上下文为全量扫描的 20%–50% | 约 50%–80% |
| Skills 按任务加载 | 必要规范与索引为 20%–50% | 约 50%–80% |
| 复用脚本 | 复用时参数与说明为重复源码生成的 10%–40% | 约 60%–90% |
| 复用流程 | AI 调度与中间输出为逐步调度的 30%–60% | 约 40%–70% |
| 增量日志或指标 | 所需日志内容为重复完整历史的 5%–20% | 约 80%–95% |
| SQL 筛选与汇总 | 必要结果输入为原始明细的 5%–20% | 约 80%–95% |
| 缩小工具清单 | 客户端实际加载的定义为全量的 30%–60% | 约 40%–70% |

比例不能相加，不能直接视为整场会话或账单降幅。模型缓存价格、输入输出单价和计费方式另行核对；没有相应数据不推算账单节省。

## 需要报告的内容

普通完成报告保留任务变化与验证即可，不强行附 token 营销文案。用户问消耗时，提供：基线、输入 / 输出统计来源、优化动作、实际覆盖范围、额外成本及实测 / 估算标识。没有全量可比数据就只报告具体步骤，避免给出统一收益承诺。
