# 软件上手与 AI 接入

## 选择工作入口

| 入口 | 使用场景 |
| --- | --- |
| Desktop | 产品与项目、文档、表格、导图、源码上下文、脚本、流程、服务器、数据库、Redis 和本机 MCP |
| Local API | 本地实例初始化、服务状态、客户端连接、用户、存储、备份、安全与诊断 |
| 云端服务 | 账号与权益、云端项目及协作内容；软件发行包提供预设地址 |
| 外部 AI 工具 | 使用平台 MCP 处理获准对象，使用自身文件与命令工具处理本机仓库 |

使用可用且获准的 UI 自动化能力操作软件；若当前环境没有该能力，给出具体页面、字段和完成标准。不要声称已点击、保存或接入。无需为了讲解界面启动实际写操作。

## 首次使用与团队连接

自行搭建实例时，在 Local API 登录云端账号，进入“初始化与恢复”，选择可读写数据目录并按本机或内网场景配置。等初始化完成，在“服务状态”核对就绪、授权与连接检查。管理员在“用户与权限”维护成员，通过“客户端连接”提供连接信息。

团队成员在 Desktop 登录正确云端账号，到“服务连接”导入管理员提供的完整连接信息，核对地址、实例与证书指纹。连接成功后，到“产品与项目”选择工作项目，核对成员角色，再打开目标内容。

- 本机个人使用可以在一台电脑运行 Desktop 与 Local API。
- 其他电脑连接 Local API 使用实际 IP 或域名；`127.0.0.1` 指向调用方自己，`0.0.0.0` 只是监听值。
- 云端账号、实例连接资格和项目成员授权独立检查。服务在线不代表该账号能看到所有项目。
- 便携发行保留 Desktop 的 `platform-mcp.exe`、`runtime/` 及 Local API 的 `license-payload.bin` 等配套文件；安装位置以当前软件为准。
- 图文操作可查 Desktop“使用说明”；连接诊断可查 Local API“诊断日志”。

## 日常操作与任务交接

- “工作台”用最近访问、收藏与继续工作返回已有对象；历史记录只是入口，不是对象备份或权限凭证。通知、保存冲突与失败运行需要打开对应对象核对实际状态。
- 顶部项目选择、侧栏分组和快速查找用于切换工作。切换后核对对象归属，不能将界面标题直接当作 MCP 项目授权。
- “设置”分别管理账号资料、密码、服务 / 构建信息、MCP 接入与 Markdown 等显示偏好；外观或历史清理不应顺带修改项目与授权。
- “使用说明”查具体模块与操作步骤；“意见反馈”提交问题、步骤和必要脱敏截图。没有实际提交能力时提供已整理材料，不能声称反馈已发送。

## 接入平台 MCP

1. 保持 Desktop 运行、账号登录有效、需要的 Local API 连接在线，选择目标项目。
2. 在“设置 → AI 接入”选择默认项目和授权项目白名单，只选择当前工作所需的工具能力、权限预设及连接白名单。
3. 选择真实 AI 客户端及传输方式，启动网关，使用软件生成的完整配置合并到该客户端的设置；保留其他服务配置。
4. 让 AI 客户端重载连接，检查实际可用工具，用一个已知 ID 完成小范围读取。已获写授权时，可用本任务的一项可逆修改及回读验证写入；只读任务不需要测试写入。
5. 确认 Desktop 中的对象内容、修订或运行结果符合预期。配置已复制或网关已启动，都不是任务执行完成的证据。

参数或客户端集合需要修改时，按软件要求停止网关再修改；修改项目、权限或传输后重新导出并加载配置。避免为每个普通工具调用重复重连。

## 接入后由 AI 主动调用

技能已被客户端加载且平台 MCP 可用时，用户只需给出任务、目标与必要 ID，AI 应主动发现工具、读取目标上下文、在现有授权内执行并回读，无需每次重复要求“使用 MCP”。调用细节见 [MCP 调用约定](mcp-contract.md)。

技能文件提供执行指引；MCP 的安装、启用、连接与工具发布仍由客户端和平台负责。用户说“之前已配置”时，先检查本聊天实际工具与配置来源，区分未加载、启动失败和模块缺失，不能据此要求用户从头配置或直接转去操作界面。

## 传输与客户端差异

- `stdio`：客户端直接启动本机 MCP 程序，以 `command` 与 `args` 数组传参。程序路径来自实际安装位置，不手工拼接 Shell 命令。
- Streamable HTTP：使用软件生成的 `127.0.0.1` 动态端口及随机路径。按目标客户端复制其专属地址，重启后重新核对；不要硬编码示例端口或改为旧 `/sse` 地址。
- HTTP 地址含敏感随机令牌，只放本机运行配置；反馈与公开文档中脱敏。不额外填写平台内部 Bearer Token。
- 平台本机 MCP 网关与团队 Local API 是不同网络入口。不要为了接入 AI 把网关暴露到公网、内网监听或隧道；WSL、容器、SSH Remote 与宿主机的回环地址不能混用。

设置页提供 Codex、Cursor、Claude Code、TRAE、Qoder IDE / CLI、Qwen Code、Kimi Code CLI、Cherry Studio、VS Code + GitHub Copilot、Cline、Gemini CLI、JetBrains AI Assistant、Zed 模板。模板实现不等于所有安装版本都已联调通过。

遇到配置差异时，优先重新生成所选客户端模板；Qoder 分别选择 IDE 或 CLI。只有手工排查时才核对该客户端使用的 JSON / TOML 根字段与 HTTP 类型，不把一种客户端冒充成另一种。

## 交给 AI 的信息

给出项目 ID、对象 ID 或 Content ID、具体目标、允许修改范围和验收要求。可以用对象面板的“交给 AI”，也可以复制 ID 附上任务。

任务示例：

> 将协作平台项目 <项目 ID> 中文档 <文档 ID> 的退款说明更新为 <具体要求>。先看大纲并定位退款段落，保留其他内容和现有格式；修改后回读该段落，报告修订与变化。

这是任务描述，不是可直接执行的工具参数。真实 ID 从软件或工具返回取得，不能使用猜测值。

## 上手时节省 token

首次只核对连接和目标对象，避免全量列出所有项目、文档与资产。针对目标模块启用能力，必要时再增加；不要自动把整套平台手册、日志和全部项目规范放进每次对话。
