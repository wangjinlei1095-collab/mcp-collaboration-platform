# 开发上下文、接入仓库与代码交付

平台提供项目背景、代码位置、逻辑线与研发规则；真正的源文件编辑、构建、测试和 Git 由 AI 当前获准的仓库工具完成。两类结果应分别核实。

## 先确认本机与平台指向同一工作

从用户提供的项目、仓库目录和任务确定目标，读取仓库适用的工作约束。按需要用 `branch_context_get` 核对绑定与 Git 状态，以本机实际分支、路径、文件内容为准。

- 目录绑定、新建 / 编辑项目和项目成员在 Desktop 办理，不构造未公布的绑定创建或项目编辑工具。
- 不将平台目录快照当成本机最新源码；哈希或分支不一致时只核对相关文件并刷新必要索引。
- 本机没有仓库访问能力时，可以整理平台上下文，但不能声称代码、测试或 Git 操作已经完成。

## 用最小上下文找到改动位置

| 所需内容 | 路径 |
| --- | --- |
| 目录与符号 | `visual_tree_get` 按父节点懒加载；`visual_node_get` 查看单个节点 |
| 已知路径、符号或 Content ID 的代码位置 | `code_location_search` 使用真实筛选字段；需要定位详情再 `code_context_get` |
| 代码位置的业务说明 | `visual_node_content_ids`、`visual_node_documents_list` / `visual_node_document_get` |
| 功能逻辑线 | `visual_logic_map_list` → 目标 `visual_logic_nodes_list` → 目标说明文档 |
| 当前任务规范 | `project_skill_list` 按 `task_type` / `module` / `path_scope` 筛选 → 对应 `project_skill_get` |

`code_context_get` 返回位置元数据，不是源码正文。先由平台缩小范围，再用本机文件工具读取相应文件和行段；不要把整仓源码写到平台说明、错误报告或长提示中。

索引任务使用 `visual_index_create` / `visual_index_status` 跟踪；仅在索引缺失或确实影响本次定位时刷新。取消或管理索引走软件实际支持的入口，不猜测 MCP 取消工具。

## 从新项目到存量仓库

新项目先在 Desktop 确定产品、项目目标与范围，绑定真正的代码目录；按任务需要创建功能导图、逻辑说明、已发布研发规则及验收依据。避免为了接入自动生成大量空节点、空文档或重复规范。

接入存量仓库先查看现有绑定、入口文件、目标模块、构建方式及代表性路径，再建立缺失的业务关联。索引只是辅助，关键结论仍需由实际源码与测试支持。不要以“接入”为由重排仓库或批量重写既有说明。

## 逻辑线、安全边界与配置集

逻辑线可通过当前可用的 `visual_logic_map_*`、`visual_logic_node_*` 和 `visual_logic_document_*` 创建草稿或原地修改说明。使用原 ID 与修订，保留源码关联、父节点和坐标；只有实际提供写入接口时才修改对应对象。

`visual_security_boundary_create`、`visual_configuration_set_create` 等用于草稿。实际生效、发布、驳回或恢复按 Desktop 的角色与审批入口完成，AI 不自我审批。

`visual_configuration_set_skills_set` 替换整个 Skill 绑定集合，保留任务未涉及的有效绑定；Skill 版本由服务端锁定。边界或规则只是约束，不扩大当前用户、工具、源码或资产权限。

## 交付与验证

1. 根据用户目标和相关规范修改本机必要文件；优先局部补丁，保留无关变更。
2. 执行与改动相称的实际验证；失败时报告真实错误。涉及代码行为时核对测试，纯文案或低影响可逆修改不为覆盖率额外堆叠测试。
3. 将必要的业务、验收或逻辑说明原地更新到平台，并回读相关对象；目录 / 符号变化时再刷新相关上下文。
4. 报告修改文件、平台对象 ID、验证结果与未决项。Git 提交、推送、合并、部署或平台发布依据本次用户授权与真实工具能力办理。

若当前会话提供独立的任务启动、需求、测试记录或变更集接口，按实际 schema 维护当前任务所需记录与人工审批状态；不能因为历史技能提过它们就假设接口存在，也不为普通改字任务固定创建整套记录。

## 节省 token

只加载相关 Skill 正文、目标业务说明和所需源码；保留仍有效的定位信息。复用测试摘要与实际结果，不在每次检查时重新扫描整仓、读取全部配置或重写整份设计文档。缩小上下文前先确保依赖与验收范围足够。
