# Word 与富文本文档

用于 Desktop“文档管理”及 `doc_*` MCP 工具。项目节点的 Markdown 说明另见项目与知识指引，不能将两族文档 ID 混用。

## 定位与读取

已知文档 ID 时直接读取。需要查找时先用 `doc_list` 的名称和说明选目标；需要目录 ID、文档清单或模块限制时用 `office_context_get(kind=word)`。不要固定同时调用所有列表与上下文。

| 需要的信息 | 优先选择 |
| --- | --- |
| 章节结构和标题 ID | `doc_get`，`format=outline` |
| 某个关键词所在段落 | `doc_find`；它可能返回整块文本，关键词应具体 |
| 可阅读的局部正文 | `doc_get`，`format=markdown`，按 `after` / `limit` 读取 |
| 保留样式的编辑基线 | `doc_get`，`format=blocks`，取得目标块完整结构 |
| 版本和变更来源 | `doc_versions_list`，必要时 `doc_version_get` |

大纲与搜索用来定位；若需保留字体、颜色或对齐，再读取目标块的结构化数据，不能根据纯文本重建样式。`after` 表示从该块之后开始，不能把它误作包含该块的起点。

## 选择最小写入

- 新建：`doc_create`，提供有辨识度的名称与必填 Markdown `description`；需要时用 `markdown` 建初始正文。目录 ID 来自有效目录列表。
- 改名称、说明、目录或页面：`doc_update`。不能通过它修改“允许 AI 编辑”或授权。
- 改一段：`doc_block_update`。它整体替换一个块，保留该块原来的类型、行内 runs 和未涉及的属性后再提交。
- 新增、删除或调整一部分：`doc_block_insert` / `doc_block_delete` / `doc_block_move`。`after_block_id` 为空字符串可表示开头，具体按对应 schema。
- 整篇重写：仅在用户确实需要全文替换并接受其表示能力时使用 `doc_markdown_set`。

Markdown 无法表达完整字体、字号、颜色、对齐、缩进和复杂表格属性；整篇转换会丢失相应格式。用户要求“只改内容、保留格式”时，不能选择 Markdown 全量覆盖。

编辑已有块先取得当前文档修订，并随写入发送支持的 `base_revision`。连续修改优先使用成功响应中的新修订；冲突时只刷新相关内容再合并，不强行覆盖。

## 导入、导出与历史恢复

Desktop 可导入 / 导出 `.docx`，展示预检结果、版本和人工 / AI 审计。当前 MCP 文档工具主要交换正文与结构化块，不能凭空构造本地文件导入 / 导出接口。

用户要求外部 Word 文件时，按实际可用的软件入口或获准文件工具完成，并查看实际产物。没有 UI 或文件操作能力时，准确说明已保存的平台内容及还需哪一步导出。

`doc_version_get` 可能返回不晚于请求修订的最近快照，必须检查实际返回的 `revision`，不能将它标为精确恢复了请求版本。恢复先比较差异，再使用软件已有入口或明确支持的写入方式。

## 验证与节省 token

普通局部编辑回读目标块与相邻必要内容，核对文字、样式、位置和新修订；整篇重构才需要更大范围结构核对。报告段落 / 块 ID 与修改摘要，避免重复回贴全文。

推荐路径：大纲或关键词定位 → 目标块 → 局部修改 → 小范围回读。大纲不是全文审阅证据；用户要求全篇校对时应逐段覆盖必要正文，并记录实际覆盖范围。
