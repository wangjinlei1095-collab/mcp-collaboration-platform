# Redis、Key 与订阅

用于 Desktop“缓存库管理”及 `cache_*`。软件支持连接、目录、人工与 AI 账号、项目关联、DB / Key / 频道范围及授权；MCP 在有效权限内执行。

## 建立最小上下文

已知连接时用 `cache_context_get`；未知时小页 `cache_connections_list`。核对项目、连接 ID、有效账号与验证状态、允许 DB、Key / 频道前缀、操作类别和结果预算。

通过 `cache_session_open` 打开或复用本任务可用的会话，保存 `cache_session_id`。Key 操作明确传 `db`；频道授权与 DB 无关，发布、订阅工具未公布 `db` 时不能添加该字段。

## 查找与读取

| 需求 | 做法 |
| --- | --- |
| 查找指定范围的 Key | `cache_keys_scan` 传获准 `match`、类型与小 `limit`，沿用原会话游标 |
| 读一个 Key | `cache_key_get`，按实际类型、游标和限制读取，核对 TTL 与截断情况 |
| 读运行指标 | `cache_server_info_get`，需要 observe 权限 |
| 排查慢命令 | `cache_slowlog_get`，只包含脱敏时间和命令名等有限内容 |

优先目标 Key 或前缀，不用全库枚举替代定位。完整扫描沿用返回游标直到 `0`；中途空页不代表结束。Redis 扫描可能重复 Key，期间数据也可能变化；需要一致性结论时明确这一限制并采用任务允许的核对方法。

String、Hash、List、Set、ZSet、Stream 的分页和返回结构不同；先读取当前类型，不根据 Key 名猜类型。大值只取必要字段、成员、范围或样本；需要完整处理时由程序分页汇总。

## 结构化命令与二进制内容

`cache_command_execute` 提交一条结构化 `args` 数组，依实际命令、Key、DB 与授权校验。只使用当前支持命令，不把多条命令拼成一个字符串或借 `EVAL` 等入口绕过拒绝。

参数可为字符串，或真实 schema 支持的 `encoding` / `data` 对象。二进制数据使用 Base64；不要把编码内容当成 UTF-8 文本改写。改 Key 内容、成员、分值或 TTL 时，核对目标类型与保留要求。

- 设置值、改名、删除、TTL 调整均可能影响业务；按用户明确的目标范围执行，批量操作先限定 Key 集合。
- 单条命令被拒绝不能据此判断整个连接只读。Key 读写与运行指标分别授权。
- 当前接口以专用指标工具代替原始 `INFO`，不支持 `CONFIG GET/SET`。有限指标不含完整持久化配置，不能由此声称已确认 appendonly 或 fsync 设置。
- 命令超时或结果未知时，先核对实际 Key / 操作结果。`INCR`、入队、发布等非幂等操作不能自动重发。

## 发布与订阅

`cache_pubsub_publish` 使用工具要求的 `[PUBLISH, 频道, 消息]` 参数形状。发布超时不自动重发。

`cache_pubsub_subscribe` 创建精确或模式订阅并返回 `subscription_id`。按 `cache_pubsub_messages_read` 的 `after` 游标增量读取，检查丢弃数量、断线缺口和缓冲限制；消息不持久化，不能把当前缓冲称为完整历史。

达到用户指定的观察目标或结束任务后，调用 `cache_pubsub_unsubscribe`，再按需要关闭本任务会话。没有明确持续监控能力时，不承诺在对话结束后继续收消息。

## 验证、报告与节省 token

修改后小范围回读值、类型、TTL 或成员变化，报告连接、DB、Key 范围、结果及截断 / 缺口。取消订阅并关闭本任务创建的空闲会话，不处理其他任务的连接。

用 Key / 前缀定位、类型分页、目标字段、指标与增量消息代替全库和历史全量输出。程序可以处理全量并向模型提供摘要，但不能因节省 token 忽略缺失消息、扫描局限或必要验证。
