# 项目、产品与业务知识

## 软件入口与对象选择

Desktop“产品与项目”维护产品定位、目标用户、价值、范围、项目、成员、版本与里程碑。新建 / 编辑项目及成员授权走软件提供的入口；用产品或项目 ID 让 AI 关联到准确对象。

产品与项目页还可维护版本和里程碑的目标、日期、验收标准与进度。项目拥有者、编辑者和只读成员按实际角色权限协作；成员管理与里程碑入口不能据名称推测为 MCP 工具。

项目导图支持文件夹、思维导图、流程图、节点 Markdown 说明、连线、业务线和内容关联。节点文档不是 Word 文档；节点说明使用 `document_*`，Office 使用 `doc_*`。

已有项目 ID 时用 `project_get` 验证；只有目标不明确才小页 `project_list`。仅在任务涉及产品归属、产品资料或空产品删除时，再读 `product_list` / `product_get`。不对每项内容编辑固定读取全产品背景。

## 读取知识的短路径

- 已知节点：`node_get` → 需要正文时 `document_list` → 选中 `document_get`。
- 已知导图：`map_get` 取得元数据；尚无根节点 ID 时，用返回的 `content_id` 调 `content_children` 找到根节点，再以真实节点 ID 调 `node_children` 逐层读取。连线相关任务再调 `relation_list`，节点挂载子图用 `node_child_maps`。
- 已知 Content ID：用 `content_resolve` 或 `content_get` 校验引用；需要指定分支时用 `content_subtree_get`，复用快照并限制页面与预算。
- 只知道名称：从项目内的相关导图列表缩小范围。只有实际会话提供搜索接口时才使用，不猜测历史文档中的搜索工具。

`map_get` 不包含整张图的节点和连线。只读取了一页或一个分支时，不能声称检查了整个项目。

## 创建与维护导图

| 目标 | 做法与关键约束 |
| --- | --- |
| 创建导图 | `map_create`，使用当前项目修订；`map_type` 与 `display_mode` 按 schema，展示可选 `mind_map` / `flowchart` |
| 建立层级 | 第一根节点不传 `parent_node_id`；同一图只有一个活动根，其后节点明确父节点，并提供 `node_type`、`sort_key` 与最新图修订 |
| 修改节点 | `node_update` 原地改标题、类型、父节点、顺序或属性，保留节点 ID 和关联 |
| 修改说明 | `document_create` / `document_update`，只编辑本次需要的说明文档 |
| 创建关系 | `relation_create` 连接同一图中的活动节点，关系类型按 `flow` / `dependency` / `reference`；父子层级仍由父节点字段表示 |
| 分类连线 | `business_line_*` 管理业务线，`relation_update` 指定归属；颜色为有效非纯白 `#RRGGBB`，同图名称与颜色不重复 |
| 管理文件夹 | `map_folder_*` 使用真实父目录和对象修订；移动或级联删除先核对影响范围 |

知识流程图允许业务连线回环；可执行的流程测试图禁止环，不能混用两套规则。

节点关联文档、表格区域或流程记录时，使用软件实际提供的专用关联入口；不能通过通用属性补丁新增、篡改或删除受保护的 `context_links_v1`。

节点 `attributes` 可能整体替换，改坐标前保留原有其他字段。手动坐标用 `flowchart_x` / `flowchart_y`；明确需要全图重排时才使用 `reset_flowchart_layout`，因为它会清除手动位置。

`node_update` 的 `content_blocks` 是完整列表替换，需保留既有块的 `content_id` 与修订；只改一个说明时优先 `document_update`。`owner` 记录创建来源，不是禁止编辑的锁；按用户授权编辑并在必要时说明修改了哪份人工内容。

## 新项目与存量知识整理

新项目先在软件明确目标、范围、成员和验收，再创建任务实际需要的导图与文档。不要预设每个项目都必须生成同一组空图或长模板。

存量项目先抽取目标模块的关键节点、现有命名和内容关联，再补充缺口。修正原对象，避免删除重建导致 ID、关系和坐标丢失。发现重复节点先确认引用与差异；“整理”本身不等于授权批量删除。

## 完成与 token 节省

写入后回读改动节点、说明和相关连线；创建结构时核对根、父子、顺序和实际新修订。报告新增或修改的 ID 与范围，不回贴整张图。

优先复用已有项目说明和 Content ID，读取相关分支即可。规则、验收和业务背景保存到合适的持久对象，后续任务按引用读取；这不等于 AI 自动永久记住这些内容，读取仍会占用 token。
